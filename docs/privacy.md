# Privacy and content boundaries

This release contains reusable instructions, reviewed source and synthetic examples. Original books, original personal databases, credentials, private history and personal media are not release inputs. The optional real book-knowledge database request remains separate from the synthetic collection shipped here; see docs/capabilities.md.

Put owner-specific records, imported books, databases, outputs and source-location details under ignored local/ folders. Never commit API keys, cookies, tokens, session files or signed URLs. Authenticate through your host's normal mechanisms. An ignore rule does not encrypt files, prevent forced staging, or control host/provider logs and retention.

Instructions cannot grant permissions or enforce a sandbox. Confirm the host's actual restrictions before handling sensitive content. Search and connector calls can transmit information: send only relevant approved data. Do not assume a private repository settles rights to share third-party content.

For a database export, inspect allowed tables, source scope and privacy fields; rebuild into a clean file rather than copying a live store with residual/deleted content. Preserve attribution and provenance. Rights status must be recorded separately from owner approval. MIT for the software does not relicense imported books.

Private GitHub releases require authorized account access; there are no embedded credentials or bearer links. Invitations and permissions belong to the owner. Recipients can retain downloaded files. MIT-covered source may be redistributed under MIT; repository visibility is not a replacement license.
