# Contributing

Use a separate branch and a narrow change with meaningful verification. Preserve role boundaries, raw inputs, privacy and evidence requirements. Never commit personal records, source books, real account data or generated private corpora. Use synthetic fixtures.

Explain the before/after behavior, tests actually run and remaining limits. Keep canonical roles in pack Markdown and adapters as references. Regenerate the release manifest after changes. Live provider calls and integration tests must be opt-in, explicitly budgeted and separated from offline checks. No claims of cross-provider compatibility without test evidence.
